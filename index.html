استفاده صحیح از پی‌را

راهنمای فارسی و مرحله‌به‌مرحله پی‌را بر پایه مستندات فعلی پروژه: تعهدهای مالی، تسویه زنجیره‌ای، یادداشت‌های انتقال، دفتر کل، دسترسی‌ها، پشتیبان‌گیری و عیب‌یابی.

مطالعه: حدود ۸ دقیقه راهنمای کاربری رابط راست‌چین (RTL)
نکته مهماین راهنما بر اساس README و ساختار مستندشده نسخه فعلی مخزن PayRa تهیه شده است. پیش از اجرای عملیات حساس، نسخه نصب‌شده و مجوز حساب را بررسی کنید. یادداشت انتقال، آرشیو و حذف نرم به‌تنهایی به معنی جابه‌جایی وجه نیستند.

نصب و راه‌اندازی

دستورهای رسمی README برای راه‌اندازی یک نصب تازه.

  1. Python نسخه ۳.۱۱ یا بالاتر نصب کنید.
  2. محیط مجازی بسازید و وابستگی‌ها را نصب کنید: python -m venv venv، سپس در PowerShell .\venv\Scripts\Activate.ps1 و pip install -r requirements.txt.
  3. فایل محیطی را بسازید: Copy-Item .env.example .env. مقدار SECRET_KEY را با مقدار تصادفی امن جایگزین کنید.
  4. پیش از اولین اجرا، گذرواژه مدیر پیش‌فرض را از طریق PAYRA_DEFAULT_ADMIN_PASSWORD در فایل .env تغییر دهید.
  5. پایگاه داده و داده‌های اولیه را با python -m flask --app run init-db ایجاد کنید.
  6. سلامت نصب را با python tools/smoke_test.py بررسی کنید و سپس python run.py را اجرا کنید.
حساب مدیر راه‌اندازینام کاربری پیش‌فرض admin و گذرواژه مستندشده admin123 است. این گذرواژه را فوراً تغییر دهید. تا قبل از تغییر آن، سرور دسترسی به سایر بخش‌ها را مسدود می‌کند؛ بهتر است مقدار محیطی را قبل از نخستین اجرا تنظیم کنید.

برای اجرای بررسی توازن دفتر کل: python -m flask --app run check-ledger. برای اجرای آزمون‌ها: python -m pytest، یا فقط آزمون‌های مالی با python -m pytest -m financial و آزمون‌های امنیتی با python -m pytest -m security.

معرفی پی‌را

پی‌را برای سامان‌دهی سوابق مالی و پیگیری تعهدات میان اشخاص طراحی شده است.

با استفاده از پی‌را می‌توانید اطلاعات مربوط به بدهی‌ها و طلب‌ها را ثبت کنید، موارد انجام‌شده را بایگانی کنید و از گزارش‌ها و لاگ‌ها برای بررسی سابقهٔ عملیات کمک بگیرید. دقت داده‌های ورودی و ثبت منظم تغییرات، پایهٔ استفادهٔ قابل‌اعتماد از سیستم است.

02

پیش از شروع

چند بررسی ساده، احتمال خطا در سوابق مالی را کاهش می‌دهد.

  • مطمئن شوید وارد حساب کاربری درست شده‌اید و مجوز لازم برای عملیات موردنظر را دارید.
  • نام طرف‌حساب را از فهرست اشخاص انتخاب کنید؛ از ساخت چند شخص با نام‌های تقریباً یکسان خودداری کنید.
  • قبل از ثبت مبلغ، واحد پولی و تعداد رقم‌های واردشده را دوباره بررسی کنید.
  • تاریخ ثبت را از تاریخ سررسید جدا در نظر بگیرید؛ این دو مفهوم یکسان نیستند.
  • برای عملیات حساس مانند حذف یا آرشیو، ابتدا جزئیات مورد را بررسی کنید.
قاعدهٔ طلاییاگر برای یک تراکنش سند، رسید یا یادداشت معتبری دارید، اطلاعات آن را هم‌زمان با ثبت مورد وارد کنید تا بعداً امکان تطبیق آسان‌تر باشد.
03

گردش کار پیشنهادی

یک روند یکسان برای ثبت، بازبینی و بستن هر مورد داشته باشید.

  1. طرف‌حساب را شناسایی کنید.
    نام شخص یا مجموعه را در فهرست اشخاص پیدا کنید و از درست بودن آن مطمئن شوید.
  2. نوع مورد را انتخاب کنید.
    اگر مبلغی باید پرداخت شود، بخش بدهی‌ها را بررسی کنید؛ اگر قرار است مبلغی دریافت شود، از بخش طلب‌ها استفاده کنید.
  3. اطلاعات را دقیق وارد کنید.
    مبلغ، واحد پولی، تاریخ‌ها و توضیحات را پیش از ذخیره مرور کنید.
  4. مورد ذخیره‌شده را بازبینی کنید.
    جزئیات ثبت‌شده را باز کنید و با رسید یا توافق اصلی تطبیق دهید.
  5. پس از تأیید نتیجه، وضعیت را به‌روز کنید.
    تسویه، آرشیو یا حذف را تنها زمانی انجام دهید که مفهوم و نتیجهٔ هر عملیات را می‌دانید.
04

اشخاص و طرف‌حساب‌ها

فهرست اشخاص را به‌عنوان مرجع مشترک ثبت‌ها نگه دارید.

  • نام کامل و قابل‌شناسایی وارد کنید؛ از نام‌های مبهم مانند «مشتری جدید» برای چند نفر استفاده نکنید.
  • قبل از افزودن شخص جدید، جست‌وجو کنید تا رکورد تکراری ایجاد نشود.
  • در صورت وجود فیلد توضیحات، اطلاعات کمکی غیرحساس مانند شناسهٔ داخلی یا روش تماس کاری را فقط در صورت نیاز وارد کنید.
  • اگر نام شخص تغییر کرد، پیش از ویرایش بررسی کنید که تغییر نام باعث اشتباه در شناسایی سوابق نشود.
حریم خصوصیاطلاعات ورود، شماره کارت کامل، رمزها یا داده‌های بسیار حساس را در فیلد توضیحات وارد نکنید.
05

ثبت بدهی‌ها

برای مبلغی که باید پرداخت شود، اطلاعات را در بخش بدهی‌ها ثبت کنید.

  1. بخش «بدهی‌ها» را باز کنید و گزینهٔ ایجاد مورد جدید را انتخاب کنید.
  2. طرف‌حساب مربوط را از فهرست اشخاص انتخاب کنید.
  3. مبلغ و واحد پولی را وارد کنید؛ واحد پولی را از روی سند یا توافق اصلی تعیین کنید.
  4. تاریخ ثبت را به‌عنوان زمان ثبت در سیستم و تاریخ سررسید را به‌عنوان موعد مورد انتظار وارد کنید.
  5. در صورت نیاز، توضیح کوتاه و قابل‌فهم اضافه کنید؛ سپس اطلاعات را مرور و ذخیره کنید.
  6. پس از ذخیره، جزئیات مورد را باز کنید و درستی اطلاعات را تأیید کنید.

چه زمانی بدهی را تسویه‌شده در نظر بگیریم؟

تنها پس از تأیید پرداخت واقعی و تطبیق مبلغ و طرف‌حساب، عملیات تسویه را انجام دهید. اگر پرداخت بخشی از مبلغ است، قبل از استفاده از تسویه بررسی کنید که نسخهٔ نصب‌شده از تسویهٔ جزئی پشتیبانی می‌کند یا خیر؛ این راهنما وجود چنین قابلیتی را فرض نمی‌کند.

06

ثبت طلب‌ها

برای مبلغی که باید دریافت شود، از بخش طلب‌ها استفاده کنید.

  1. وارد بخش «طلب‌ها» شوید و ایجاد مورد جدید را انتخاب کنید.
  2. شخصی را که باید مبلغ را پرداخت کند انتخاب کنید.
  3. مبلغ و ارز را مطابق توافق ثبت کنید.
  4. تاریخ ثبت، سررسید و توضیحات لازم را وارد کنید.
  5. مورد را ذخیره و جزئیات آن را بررسی کنید.
  6. بعد از دریافت و تأیید وجه، وضعیت مورد را طبق امکانات نسخهٔ خود به‌روز کنید.
ثبت دریافت واقعییادداشت یا وعدهٔ پرداخت را با دریافت قطعی وجه اشتباه نگیرید. برای وعده یا هماهنگی انتقال، از یادداشت‌ها استفاده کنید؛ برای طلب واقعی، از بخش طلب‌ها.
07

یادداشت‌های انتقال

ثبت اطلاعاتی انتقال مورد انتظار، کاملاً جدا از دفتر کل مالی.

یادداشت مشخص می‌کند چه کسی، به چه کسی، چه مبلغی و در چه تاریخی باید انتقالی را انجام دهد. یادداشت به‌خودی‌خود پرداخت، دریافت یا تسویه مالی نیست.

فیلدرفتار تأییدشده
بدهکار (مبدأ) و طلبکار (مقصد)هر دو از فهرست اشخاص انتخاب می‌شوند؛ متن آزاد پذیرفته نیست و شناسه نامعتبر رد می‌شود.
مبلغعدد صحیح در کوچک‌ترین واحد پول؛ صفر، منفی و اعشار بیش از حد مجاز پذیرفته نمی‌شود.
واحد پولیاز فهرست ارزهای سامانه؛ پیش‌فرض ریال (IRR). تبدیل خودکار وجود ندارد.
تاریخ ثبت و سررسیدتقویم شمسی؛ هر دو به‌صورت پیش‌فرض روی امروز هستند.
وضعیت«در انتظار» یا «تسویه شده». وضعیت انتخابی است و محاسبه مالی نیست.
توضیحاتاختیاری، حداکثر ۲۰۰۰ نویسه.

عملیات و جهت انتقال

عملیات «جزئیات»، «ویرایش»، «حذف» (با تأیید) و «تسویه شده» در فهرست کشویی همان سطر قرار دارند. در فرم، جمله‌ای زنده مانند «الف باید به ب بپردازد» جهت انتقال را پیش از ثبت روشن می‌کند؛ این جمله صرفاً نمایشی است و محاسبه مالی انجام نمی‌دهد.

وضعیت در فرم ویرایش فقط خواندنی است. علامت‌گذاری به‌عنوان «تسویه شده» از فهرست یا صفحه جزئیات انجام می‌شود.

جداسازی قطعی از امور مالیایجاد، ویرایش، تسویه‌شده‌کردن یا حذف یادداشت نباید مانده اشخاص، تعهدها، تسویه‌های مالی، گزارش‌های مالی یا آرشیو تعهدها را تغییر دهد. این عملیات فقط همان یادداشت و رویداد متناظر آن را تغییر می‌دهد.

دسترسی‌های یادداشت شامل notes.view، notes.create، notes.edit، notes.delete و notes.settle هستند. رویدادهای CREATE_NOTE، UPDATE_NOTE، DELETE_NOTE و SETTLE_NOTE در گزارش رویدادها ثبت می‌شوند.

08

تسویه، زنجیره و آرشیو

تسویه عملیات مالی است؛ آرشیو و حذف رفتارهای جداگانه‌اند.

تسویه جزئی و کامل

هر تعهد دو مقدار اصلی دارد: مبلغ اولیه که پس از ایجاد تغییر نمی‌کند و مانده جاری. مبلغ تسویه‌شده جداگانه ذخیره نمی‌شود و از تفاضل مبلغ اولیه و مانده محاسبه می‌شود. وضعیت‌های فعال، پرداخت جزئی، تسویه‌شده و سررسیدشده نیز از داده‌ها محاسبه می‌شوند.

  • مبلغ تسویه باید بزرگ‌تر از صفر باشد.
  • مانده هیچ‌گاه نباید منفی یا بیشتر از مبلغ اولیه شود.
  • تسویه بیش از مانده یا تسویه با ارز متفاوت رد می‌شود.
  • کلید یکتایی از اعمال دوباره یک درخواست جلوگیری می‌کند؛ نسخه رکورد نیز تغییر همزمان را تشخیص می‌دهد.

تسویه زنجیره‌ای

تسویه زنجیره‌ای امکان انتقال متوازن ارزش از پرداخت‌کننده به دریافت‌کننده از مسیر یک یا چند تعهد پیوسته را فراهم می‌کند. بدهکار و طلبکار تعهدهای متوالی باید به‌درستی به هم متصل باشند؛ همه پایه‌ها باید ارز یکسان و مانده کافی داشته باشند.

موقعیت واسطه تغییر نمی‌کندبرای مثال، اگر «سعید → من» و «من → شاهین» هر دو ۳۰۰ باشند، تسویه مستقیم «سعید → شاهین» هر دو تعهد را صفر می‌کند و موقعیت «من» را تغییر نمی‌دهد؛ درآمد یا پرداخت جعلی ساخته نمی‌شود.

در عملیات چندپایه، سامانه ابتدا همه پایه‌ها را اعتبارسنجی می‌کند و سپس تغییرات را با خواندن تازه مانده‌ها ثبت می‌کند تا تخصیص‌های متوالی روی یک تعهد در تاریخچه گم نشوند.

ابطال تسویه

ابطال، تخصیص را دقیقاً برمی‌گرداند. اگر چند تسویه روی یک تعهد انجام شده باشد، ابطال باید به ترتیب آخرین‌تسویه‌اول (LIFO) انجام شود؛ ابطال قدیمی‌تر پیش از برگرداندن تسویه جدیدتر رد می‌شود تا دوباره‌شماری رخ ندهد.

آرشیو و حذف

عملیاترفتارمحدودیت
آرشیوبایگانی بدون تغییر مبلغ یا ماندههر عملیات دارای batch_id است و بازگردانی همان دسته امکان‌پذیر است.
حذف نرمرفتار پیش‌فرض حذف؛ رکورد و مبالغ حفظ می‌شوند.با حذف قطعی اشتباه نشود.
حذف قطعیحذف غیرقابل‌بازگشت رکوردفقط مدیر ارشد، با وارد کردن شناسه و فقط برای تعهدی که هیچ تسویه‌ای ندارد. تعهد دارای سابقه تسویه حفظ می‌شود.
09

مبلغ و واحد پولی

دقت مالی بر نمایش و راحتی مقدم است.

  • مبالغ به‌صورت عدد صحیح در کوچک‌ترین واحد پولی ذخیره می‌شوند؛ از float در مسیر مالی استفاده نمی‌شود.
  • ریال و تومان بدون اعشار ذخیره می‌شوند؛ دلار، یورو، درهم و پوند با دو رقم اعشارِ واحد کوچک (سنت) نمایش/ذخیره می‌شوند.
  • تبدیل ارزی خودکار وجود ندارد. نمایش ریال به تومان تنها تبدیل دقیق ۱۰ به ۱ است و فقط نمایش را تغییر می‌دهد، نه مقدار ذخیره‌شده.
  • جمع‌ها همیشه به تفکیک ارز گزارش می‌شوند؛ جمع ساده ریال و دلار معنی مالی ندارد.
  • تفاوت ارز در یک تسویه رد می‌شود. برای مقایسه ارزها، نرخ و تاریخ تبدیل را جداگانه مشخص کنید.
عدد ذخیره‌شده را با نمایش اشتباه نگیریدریال به تومان فقط برای نمایش تبدیل می‌شود. هیچ نرخ تبدیل خودکاری برای ارزهای دیگر فرض نکنید و مبلغ را با سند اصلی تطبیق دهید.
10

گزارش‌ها، دفتر کل و لاگ‌ها

گزارش برای جمع‌بندی و لاگ برای بررسی رخدادهاست.

  • گزارش‌ها و خروجی‌ها را به تفکیک ارز بررسی کنید و با اسناد اصلی تطبیق دهید.
  • گزارش رویدادها زمان، کاربر، نوع عملیات، شناسه موجودیت، خلاصه فارسی، IP و جزئیات ساختاریافته را برای عملیات مهم ثبت می‌کند.
  • گزارش رویدادها فقط‌افزودنی است؛ مسیر ویرایش یا حذف رویداد وجود ندارد.
  • رویداد و تغییر مالی در یک تراکنش ثبت می‌شوند تا سابقه از تغییر مالی جدا نماند.
  • برای بررسی توازن دفتر کل، دستور python -m flask --app run check-ledger را اجرا کنید؛ در صورت عدم توازن، کد خروجی غیرصفر می‌دهد.
  • خروجی‌های Excel و PDF در سامانه وجود دارند و تابع سطح دسترسی و سقف سطرها هستند.
گزارش جایگزین سند نیستپیش از تصمیم مالی مهم، خروجی را با رسیدها و سوابق معتبر تطبیق دهید.
11

نقش‌ها و دسترسی

مجوزها در سمت سرور بررسی می‌شوند.

  • هر کاربر باید با حساب مجاز خودش کار کند؛ حساب مشترک نسازید.
  • هر مسیر عملیاتی در سرور مجوز لازم را بررسی می‌کند؛ پنهان بودن دکمه در رابط کاربری به‌تنهایی کنترل امنیتی نیست.
  • اصل کمترین اختیار را رعایت کنید. مجوزهای ویژه مدیر ارشد به مدیر عادی قابل اعطا نیستند.
  • دسترسی‌های ردشده نیز در گزارش رویدادها ثبت می‌شوند.
  • حذف قطعی تعهد فقط برای مدیر ارشد و با محدودیت‌های مشخص‌شده در بخش آرشیو و حذف مجاز است.
12

پشتیبان‌گیری، پایگاه داده و بازیابی

نسخه پشتیبان باید سازگار و قابل‌بازیابی باشد.

  1. پیش از به‌روزرسانی یا تغییر مهم، نسخه پشتیبان سازگار تهیه کنید.
  2. در نصب پیش‌فرض SQLite، فایل پایگاه داده در instance/payra.db قرار دارد.
  3. برای پشتیبان SQLite از VACUUM INTO استفاده کنید یا ابتدا نوشتن در پایگاه داده را متوقف کنید؛ کپی ساده هنگام نوشتن ممکن است سازگار نباشد.
  4. فایل پشتیبان را جدا از محیط اصلی و در محل امن نگه دارید و دسترسی آن را محدود کنید.
  5. بازیابی را دوره‌ای در محیط آزمایشی امتحان کنید.

راه‌اندازی پایگاه داده در نصب تازه

پس از نصب وابستگی‌ها و تنظیم فایل محیطی، دستور رسمی ساخت پایگاه داده و داده‌های اولیه این است:

python -m flask --app run init-db

این دستور جدول‌ها، ارزها و تنظیمات پیش‌فرض را می‌سازد، شخص «من» را ایجاد می‌کند و مدیر ارشد را با گذرواژه هش‌شده می‌سازد.

بررسی ساختار و ارتقای پایگاه داده

برای تشخیص وضعیت ساختار از python -m flask --app run db-verify و برای اعمال مهاجرت‌ها از python -m flask --app run db upgrade استفاده کنید. create_all() ستون‌های جدید را به جدول‌های موجود اضافه نمی‌کند.

داده‌های موجود را حذف نکنیداجرای دوباره راه‌اندازی یا حذف فایل پایگاه داده می‌تواند اطلاعات را از بین ببرد. حذف و ساخت مجدد فقط وقتی مناسب است که داده‌ای برای حفظ‌کردن وجود ندارد.

امنیت و خطاهای رایج

چک‌لیست عملی برای استفاده و عیب‌یابی.

کنترل‌های امنیتی

  • گذرواژه‌ها با scrypt هش می‌شوند؛ متن خام گذرواژه ذخیره نمی‌شود.
  • درخواست‌های تغییردهنده با CSRF محافظت می‌شوند؛ نشست از کوکی‌های دارای تنظیمات امنیتی استفاده می‌کند.
  • پس از ۵ تلاش ناموفق، حساب قفل می‌شود؛ تلاش‌ها بر پایه IP نیز محدود می‌شوند.
  • در محیط عملیاتی، SECRET_KEY قوی و HTTPS همراه با SESSION_COOKIE_SECURE=true لازم است. پیکربندی عملیاتی با کلید پیش‌فرض اجرا نمی‌شود.
  • اسرار را در کد یا یادداشت‌های مالی ذخیره نکنید و اطلاعات واقعی را در تصاویر عمومی منتشر نکنید.

آزمون‌ها و استقرار

پیش از انتشار، رفتار مالی و امنیتی را آزمایش کنید.

دستورکاربرد
python -m pytestاجرای همه آزمون‌ها
python -m pytest -m financialآزمون‌های دقت مالی
python -m pytest -m securityآزمون‌های امنیتی
python tools/smoke_test.pyبررسی سلامت نصب و صفحه‌ها
python -m flask --app run check-ledgerاعتبارسنجی اتحادهای دفتر کل

آزمون‌های پروژه حوزه‌های محاسبات، تعهدها، تسویه جزئی و کامل، تسویه زنجیره‌ای، ناورداهای مالی، آرشیو و حذف، اشخاص، یادداشت‌ها، احراز هویت، مجوزها، تنظیمات، خروجی‌ها و بارگذاری صفحه‌ها را پوشش می‌دهند.

استقرار عملیاتی

  • روی ویندوز می‌توان از Waitress استفاده کرد؛ روی لینوکس، Gunicorn.
  • در محیط عملیاتی کلید محرمانه قوی، HTTPS و کوکی امن نشست را تنظیم کنید.
  • برای PostgreSQL، مقدار DATABASE_URL را تنظیم کنید؛ لایه دسترسی داده از ORM استفاده می‌کند.
  • پیش از استقرار، check-ledger را به‌عنوان دروازه سلامت اجرا کنید و سیاست‌های زمان نشست و بازگردانی آرشیو را تنظیم کنید.

پرسش‌های متداول

پاسخ‌های سریع به چند سؤال مهم.

آیا یادداشت انتقال، بدهی یا طلب را تغییر می‌دهد؟

خیر؛ یادداشت برای پیگیری است و نباید جایگزین ثبت در بخش بدهی‌ها یا طلب‌ها شود.

آیا آرشیو کردن یعنی تسویه شدن؟

نه لزوماً. آرشیو معمولاً برای خارج کردن مورد از فهرست فعال است؛ تسویه مفهوم جداگانه‌ای دارد. رفتار دقیق به نسخهٔ نصب‌شده بستگی دارد.

اگر مبلغ را اشتباه وارد کردم چه کنم؟

ابتدا رکورد و سند اصلی را شناسایی کنید. سپس از عملیات ویرایش مجاز استفاده کنید و پس از ذخیره، جزئیات را دوباره با سند تطبیق دهید. اگر مورد قبلاً تسویه شده است، پیش از اصلاح اثر تغییر را بررسی کنید.

آیا می‌توان ارزهای مختلف را مستقیم با هم جمع کرد؟

خیر، جمع سادهٔ مبالغ ارزهای متفاوت معنی مالی یکسانی ندارد. برای مقایسه باید نرخ تبدیل، تاریخ و مبنای محاسبه مشخص باشد.

آیا می‌توان رکورد حذف‌شده را بازیابی کرد؟

این موضوع به پیاده‌سازی و وجود پشتیبان یا سازوکار بازیابی بستگی دارد. حذف را برگشت‌پذیر فرض نکنید.

اگر موردی در فهرست پیدا نمی‌شود چه کنم؟

عبارت جست‌وجو، فیلترها، بازهٔ تاریخ و بخش آرشیو را بررسی کنید. قبل از ثبت دوباره، مطمئن شوید رکورد مشابهی وجود ندارد.

بخشی مطابق جست‌وجوی شما پیدا نشد. عبارت دیگری امتحان کنید.
